# SAAS_GAP_MATRIX — gaps found and their disposition

| # | Component | Current state (evidence) | Expected SaaS state | Gap severity | Disposition |
|---|-----------|--------------------------|---------------------|--------------|-------------|
| 1 | Super admin UX | Same clinic dashboard for `super_admin`; no router in SPA | Dedicated control plane | CRITICAL | Fixed: platform bootstrap branch + `PlatformConsole` (overview/tenants 360/plans/usage/support/users/audit) |
| 2 | Platform API | 4 routes, authz inside controller, no capability model | Capability-guarded control plane API | HIGH | Fixed: `EnsurePlatformAccess` middleware + `PlatformAuthorizer` capabilities (`ris.platform_roles`) |
| 3 | Plan limits | Stored, never enforced (`max_users`, `max_studies_per_month` unused in code) | Server-side enforcement | HIGH | Fixed: `EntitlementService::enforce` on study booking + staff creation (403 `quota_exceeded`) |
| 4 | Entitlements / features | `plans.features` JSON unread | Feature flags: default → plan → tenant override; API-enforced | HIGH | Fixed: `FeatureResolver` + `denyFeatureUnlessEnabled` on inventory/dicom/dispatch writes |
| 5 | Usage metering | None | Tenant-attributed, transactional meters | HIGH | Fixed: `usage_counters` (studies, reports) incremented in the domain transaction; storage computed by `StorageMeter` (real file sizes, tenant-keyed cache) |
| 6 | Tenant lifecycle | Status set by hand; trials never auto-expired; no offboarding | Lifecycle engine + sweep | HIGH | Fixed: `TenantLifecycleService` + `ris:subscription-sweep` (daily) + offboarding export + retention window + `ris:tenant-destroy` operator command |
| 7 | Multi-tenant users | Impossible (1 user = 1 `business_id`) | Global identity + memberships + explicit switching | HIGH | Fixed: `tenant_memberships` + `POST /tenant/switch` + tenant-scoped authorization (see `AUTHORIZATION_MODEL.md`) |
| 8 | Platform roles | Single `super_admin` type | Distinct platform roles (ops/billing/support/auditor) | MEDIUM | Fixed: `users.platform_role` + capability map; last-super-admin protection |
| 9 | Break-glass support | None (super admin had NO tenant access at all — platform staff could operate nothing clinically) | Audited, expiring support sessions | HIGH | Fixed: `support_sessions` + enter/leave context + full audit |
| 10 | Business::users() bug | Missing relation used by platform list → runtime exception | — | HIGH (latent crash) | Fixed: relation added; regression covered by platform tests |
| 11 | Audit attribution | `audit_logs` had no tenant column; platform actions invisible | Tenant-attributed + platform audit stream | MEDIUM | Fixed: `audit_logs.business_id` + `GET /platform/audit` + lifecycle event registry |
| 12 | Login for terminated tenants | Login always succeeded | Terminated/offboarding blocked at login; suspended/expired land on gate | MEDIUM | Fixed in `AuthController@login` + SPA `SubscriptionGateView` (402 handling) |
| 13 | SPA routing/gating | All 10 tabs for every role | Role + entitlement-gated surfaces | MEDIUM | Fixed: `ROLE_TABS` gating + entitlement-gated inventory/doctors tabs + platform console branch |
| 14 | Legacy single-tenant data | Businesses existed without control-plane records | First-class tenant registry | MEDIUM | Fixed: expand-migration backfills memberships + lifecycle history + usage baselines (no data loss) |
| 15 | Noisy-neighbor rate limits | Per-user `api` limiter only; no tenant-aggregate budget — one clinic's runaway automation could saturate shared capacity | Tenant-attributed API rate limits + platform-wide safety limits | MEDIUM | Fixed: `throttle:tenant` on the tenant data plane — aggregate per-active-tenant budget (`ris.tenant_api_rate_limit_per_minute`, default 2400/min), keyed on `getActiveBusiness()` so switched members/support sessions count against the operated clinic; isolation covered by `TenantRateLimitTest` |
| 16 | Deployment topology / regionalization | Every tenant implicitly on one undisclosed placement; no region, stamp, isolation profile, cluster or storage region; nothing recorded where a tenant physically lives | Declared placement catalog + per-tenant placement + re-placement, config-owned, audited | HIGH | Fixed: `businesses.region / deployment_stamp / isolation_profile / database_cluster / storage_region` (expand-only migration) + `ris.regions` / `ris.deployment_stamps` catalog + `GET /platform/infrastructure` and `PATCH /tenants/{id}/deployment` (`infrastructure.manage`, audited `tenant_deployment_updated`). Provisioning stamps the operator's declared default. Covered by `PlatformDeploymentTest` |
| 17 | White-labeling + custom domains | One hard-coded product brand for every tenant; no tenant-owned host could ever be served | Per-tenant presentation overrides + verified custom host registry, presentation-only | MEDIUM | Fixed: `tenant_branding` + `tenant_domains` (expand-only migration), `GET/PUT /tenants/{id}/branding` and domain add/verify/primary/remove. DNS TXT ownership proof `_polytronx-ris.<host>` = `polytronx-ris-verify=<tenant code>`; **the host is never an authorization input** — the tenant is always resolved from the session. Gated by the `branding` / `custom_domains` entitlements. Covered by `TenantBrandingTest` |
| 18 | Tenant integration registry | Integrations were ad-hoc per feature (DICOM nodes, notification templates) with no unified, secret-bearing registry and no honest health probe | One tenant/facility-scoped registry with encrypted credentials and real probes | HIGH | Fixed: `tenant_integrations` with `secrets` cast `encrypted:array` (never returned — presence + `••••••••` mask only) and genuine probes: `tcp` via `fsockopen`, `http` via `Http::get`, `config` reporting completeness **without** asserting delivery. Rotation audited (`tenant_integration_secret_rotated`). Covered by `TenantIntegrationTest` |
| 19 | Observability + operational tooling | Overview had counters only; a failed job's payload could not be inspected without DB access, a retry was impossible, and entitlement drift was invisible (the resolver silently ignores unknown keys) | Explained per-tenant health rollup + safe operational tooling | HIGH | Fixed: `TenantHealthService` (bulk aggregates; derived verdict with reasons; unmeasurable quota reports `null`, never a comfortable zero) + `JobInspector` (payload never returned; property names from **reflection on the job class**, never from the serialized payload) + `EntitlementReconciler` (reports drift; prunes only inert `stale` overrides, never contradicting ones) + real `queue:retry` / `queue:forget`. Covered by `PlatformOperationsTest` |
| 20 | `jobs` table missing | `config/queue.php` defaults to the `database` driver, but only `failed_jobs` was ever migrated — the configured queue could not accept a job | The configured queue driver must actually work | HIGH (latent) | Fixed: `2026_09_15_000400_create_jobs_table.php`. Nothing had exercised the queue (no queued work yet), so it went unnoticed until §81 required a retry to genuinely re-queue — a retry that cannot enqueue would have been a fake success |
| 21 | Route action integrity | A controller wired into `routes/api.php` without a `use` import resolved to the global namespace and 500'd the whole surface on first touch. Neither `php -l` (parses only) nor `tsc` (never reads routes) can see this | Every routed action must exist, and every platform route must be guarded | HIGH | Fixed: added the missing import (the `PlatformBrandingController` bug found in CI run #114) + `RouteIntegrityTest`, which walks `Route::getRoutes()` and fails on any action whose class or method does not exist, and asserts every `api/v1/platform` route carries the `platform` middleware |

Not gaps (verified as already correct): pooled `business_id` scoping on all domain tables; server-side tenant resolution (client business ids never trusted); per-tenant laratrust roles; tenant-scoped settings caches; export isolation; polling-only realtime (no cross-tenant channels); no search engine to isolate (client-side filtering of tenant-scoped payloads); sync queue (no async boundary to isolate).
